# 2FA 登录导入与凭证运营

入口：Codex 账号 → 添加账号 → **2FA 登录导入**。

每行 `邮箱----密码----TOTP 长期密钥`，一次最多 100 行（256 KiB）。
TOTP 为 Base32 密钥，不是六位动态验证码。支持 CRLF、尾部空白和小写密钥；密码原样保留，包括 `$`、空格及内部 `----`。测试和文档仅使用虚构资料。

## 部署

- `CREDENTIAL_OPS_KEY`：独立的、Base64 编码的 **32 字节随机密钥**。所有连接同一数据库的实例使用相同密钥。密钥与数据库配套备份；不要用管理员密码代替，不要直接换钥后丢弃旧密钥。本版没有自动生成或轮换密钥的接口。
- `TOSUB2_ROOT`：运维自行审核并固定版本的 toSub2 目录，包含 `src/protocol-login.mjs`。仓库不下载该外部协议实现，也不保证其当前登录协议有效。
- `CREDENTIAL_OPS_NODE`：可选 Node.js 可执行文件，默认 `node`。API 进程运行环境必须能找到它。
- `TOSUB2_PYTHON`：安装了协议仓库 `requirements.txt` 依赖的 Python 可执行文件；建议使用独立虚拟环境。此路径会通过白名单传给本地协议进程。还需在协议目录执行 `npm ci --ignore-scripts` 安装 Node 依赖。仅有 Node 和协议脚本不足以执行真实登录。
- 修改配置后重启服务。默认 Docker 镜像不因此自动安装 Node.js 或 toSub2；部署者需提供带这些依赖的运行环境，并显式向容器注入以上变量及挂载协议目录。仅修改宿主机 `.env` 不保证 compose 会传入自定义变量。
- Worker 本版为 **API 进程内的独立后台循环**，使用数据库持久任务与租约；并非单独部署的守护进程。首次登录与后续重登均调用本地协议适配器，不复用 sub2api 的远端首次登录服务，也不开放领取明文秘密的 Worker HTTP 接口。

## 状态与恢复

`queued → enrollment_pending → enrolled`。HTTP 202 仅表示任务受理，只有 `enrolled` 表示账号导入及凭证运营登记均完成。

- 登录结果先加密保存；之后创建或按邮箱 + OAuth 工作区复用账号。完成登记前不报成功。
- 登记失败保留加密结果和账号 ID；可手工补登记，也会自动重试。页面刷新、API 重启不丢失已保存的结果。若在协议完成但结果尚未保存时崩溃，仍可能需要重新登录。
- 同一邮箱默认幂等，不覆盖已有秘密。纠正密码/TOTP 时，明确勾选“更新已有邮箱的登录资料并重新登录”；执行中的任务拒绝覆盖。更新会清除旧登录结果并重新登录，不重复创建账号。此版本每个登录邮箱仅管理一个 OAuth 工作区，不支持一份登录资料同时托管多个工作区。
- 密码、TOTP、首次登录代理及待登记的 OAuth 结果使用 AES-256-GCM 加密，并绑定记录 ID 和用途；不会出现在普通账号导出或列表响应。
- 系统设置 → Codex → 2FA 后台任务：可设置每个实例的后台并发数，默认 2，范围 1–8。配置独立存入数据库，专用保存按钮提交，重启后保留；通过管理员 `GET/PUT /api/admin/settings/credential-operations` 读写。多个实例分别应用同一上限，并非集群总上限。
- Worker 每 5 秒检查队列和配置，空闲槽位同时领取不同账号的任务，完成任务后立即补位。登录、补登记和巡检共用并发上限；关闭导入窗口不停止后台任务。调低上限不打断执行中的任务，待任务自然结束后减少并发；配置读取失败时不再领取新任务。
- 同一账号仍通过数据库租约互斥；租约 30 分钟，单次协议登录最长 25 分钟。租约过期可由其他实例重领，旧 Worker 不能完成或覆盖新任务。调整并发不会强行清除旧租约，“等待租约释放”的账号仍需等待。
- 已登记账号每 30 分钟通过现有模型列表接口巡检；鉴权异常 5 分钟复检，401/403 累计达到 2 次触发重登；网络异常或 429 不触发重登。模型列表正常不保证所有生成请求、额度或权限可用。
- 协议登录失败停止自动重试，状态为 `login_failed`，需管理员检查资料并重试，避免持续尝试错误密码。
- 巡检或协议失败输出中识别到明确的账号停用/封禁错误码时，进入 `recovery_blocked`，关闭自动重登，不再领取巡检或登录任务；不会仅凭 HTTP 403、429、代理风控或普通错误文字判定封禁。协议 stderr 只在内存中做有界错误码检测，不记录或回传原始内容；未识别的登录失败仍按 `login_failed` 停止自动重试。
- 封禁状态持久保存，重启或暂停后恢复均不会自动解除。确认上游解封后，在导入列表手动重试（有确认提示）或显式更新登录资料才重新启用；这不是自动解封功能，也不会影响普通账号自身的其它调度机制。
- 暂停阻止后续领取并立即撤销写回权限；已启动的外部协议进程不保证立刻停止，但其结果不能提交。执行占位保留到原租约到期，恢复或更新资料不能立即启动第二个并行登录。恢复不会把管理权转移给其他机制。
- 普通 OAuth RT 刷新仍保留；它不是另一套密码重登守护。重登写回校验账号身份、工作区及凭据快照，在事务中更新 token、推进凭据代次并完成任务，保留无关配置和限速冷却。并发刷新/手工换令牌时丢弃旧重登结果。

## 边界

删除已绑定的账号（移入回收站、批量删除、彻底删除或清空回收站）会在同一事务中删除关联凭证运营记录，包括加密登录资料、待登记结果和租约。旧 Worker 的 checkpoint/save/complete 不能重新创建记录或写回结果。已发出的外部登录请求不保证立即取消，但不会再调度后续重登。恢复回收站账号不会恢复已清除的密码/TOTP，需显式重新登记。列表读取及任务领取还会清理旧版本遗留的已删除/已不存在账号的运营记录；尚未绑定账号的导入任务不按邮箱猜测关联，需要在导入列表单独暂停。

当前 codex2api 没有 sub2api 那套旧 2FA 守护，因此没有需要迁移的旧守护名单；没有新增第二套密码重登机制。若以后引入旧机制，必须以凭证运营登记为管理权依据，而不是以巡检开关决定是否避让。

API 仅允许管理员调用，返回 `Cache-Control: no-store`。外部进程 stdout/stderr 被丢弃，错误不回显输入；密码/TOTP 经子进程环境而非 shell/参数传递。协议实现依然是受信任代码；代理地址可能出现在进程参数，Worker 所在主机和临时目录需受保护。

本功能没有使用真实账号自动验收。单元测试使用合成 JWT、本地协议替身与临时 SQLite；PostgreSQL 兼容 SQL 仍需部署环境集成验收。生产启用前，应以获准测试账号验证固定协议版本、出口代理与实际登录流程。
